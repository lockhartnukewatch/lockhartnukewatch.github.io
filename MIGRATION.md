# Migration Plan: Jekyll → Astro

This site is a small static Jekyll site (theme: `minimal-mistakes-jekyll`) that will be
migrated to [Astro](https://astro.build). Work happens on the `astro` branch.

## Current State (what we're migrating from)

- **Build:** Jekyll 4.4 + Minimal Mistakes theme (gem, compiled SCSS) + `jekyll-feed`
  (`_config.yml`, `Gemfile`).
- **Publish flow:** source lives on `main`; `publish.sh` runs `jekyll build` and commits the
  output into the `_site` git submodule, which is the `gh-pages` branch of
  `lockhartnukewatch.github.io` (what GitHub Pages serves). `CNAME` lives in the published
  branch, not in source.
- **Pages:**
  | Current file | Layout | Published URL |
  |---|---|---|
  | `index.markdown` | custom `landing` (content + sidebar) | `/` |
  | `about.markdown` | `single` | `/about/` |
  | `archive.markdown` | `single` (contains a Liquid loop) | `/archive/` |
  | `404.html` | `page` | `/404.html` |
- **Collections (Jekyll):** `_topics/` (1 page), `_updates/` (3 pages), `_archive/` (5 pages),
  all published under `/topics/:name/`, `/updates/:name/`, `/archive/:name/`.
- **Templates:** `_layouts/landing.html` (title + content + sidebar aside) and
  `_includes/sidebar-collection.html` (renders nav lists from the `updates` and `topics`
  collections, with `external_url` support).
- **Assets:** `assets/css/main.scss` (imports minimal-mistakes + custom `.landing-*` sidebar
  CSS), `assets/pdf/Oklo-Texas-Q-A.pdf`.
- **Other:** `_data/navigation.yml` is empty (no theme header nav), `feed.xml` generated by
  jekyll-feed, `robots.txt` in the published branch, `.domains` / `CNAME` for
  `lockhartnuke.watch` + `www`.

## Design Decisions

1. **Do not port the Minimal Mistakes theme.** It is a large SCSS theme whose CSS is coupled
   to layout HTML we're not carrying over. Instead write one small `BaseLayout.astro`
   (site title header with links to Home / About / Archive, footer with the Facebook link and
   contact email) plus a compact base stylesheet. Keep the existing `.landing-*` sidebar CSS
   from `assets/css/main.scss` as-is — it is self-contained.
2. **Use Content Collections** for `updates`, `topics`, `archive` (dynamic routes) and plain
   markdown for `index`/`about`. This mirrors the Jekyll collections 1:1 and makes the
   sidebar easy to build with `getCollection()`.
3. **Keep all published URLs identical** (including trailing slashes) so existing links, the
   Facebook group, and any bookmarks keep working.
4. **Publish flow stays the same pattern:** `npm run build` → copy `dist/` into the `_site`
   submodule (gh-pages branch) → commit. Only the build step in `publish.sh` changes.

## Step-by-Step Plan

1. **Scaffold Astro** in the repo root:
   `npm create astro@latest` (or `npx astro init .`), choosing the empty template,
   no framework, no UI library.
   Configure `astro.config.mjs`:
   - `site: "https://www.lockhartnuke.watch"`
   - `output: "static"` (default)
   - `trailingSlash: "always"` to match current Jekyll permalinks.

2. **Move content files** (markdown bodies are unchanged, only locations/front matter):
   - `_updates/*.markdown` → `src/content/updates/*.md`
   - `_topics/*.markdown` → `src/content/topics/*.md`
   - `_archive/*.markdown` → `src/content/archive/*.md`
   - `about.markdown` → keep its body in `src/pages/about.astro` (or a content doc — either
     is fine; a plain page is simplest since it has no dynamic data).
   - `assets/pdf/Oklo-Texas-Q-A.pdf` → `public/assets/pdf/`.
   - Front matter changes per file:
     - drop `layout:` keys (no meaning in Astro).
     - add an explicit `date` to `updates/*` files (Jekyll currently derives dates from the
       filenames `YYYY-MM-DD-name`; Astro does not). Format: `date: 2026-05-08`.
     - keep `title` on everything (used for `<h1>`, `<title>`, and sidebar links).
   - Define collections in `src/content.config.ts` with a `title` (required) and optional
     `date` / `external_url` schema so the sidebar's `external_url` feature survives.

3. **Build the base layout** (`BaseLayout.astro`):
   - `<head>`: site title, per-page title, meta description from `_config.yml`, viewport.
   - Header: "Lockhart Nuke Watch" → `/`, nav links About, Archive (current site has no
     visible nav; adding these is a small improvement — note it as such).
   - Footer: Facebook group link + `contact@lockhartnuke.watch`.
   - `global.css`: simple, readable article typography (max-width ~70ch, link colors,
     headings, blockquote styling since updates use blockquotes heavily) plus the existing
     `.landing-wrapper / .landing-content / .landing-sidebar` rules.

4. **Build the pages:**
   - `index.astro`: markdown body from `index.markdown` (inline it as markdown or use
     `render()` on a stored doc), wrapped in the landing structure: content + `<Sidebar>`
     fed by `getCollection("updates")` and `getCollection("topics")`.
   - `components/Sidebar.astro`: port of `_includes/sidebar-collection.html` — takes a list
     of `{ name, title, items }`, renders `<h3>` + list; supports `external_url`
     (target=_blank rel=noopener) vs internal `/collection/slug/` links.
   - `updates/[slug].astro`, `topics/[slug].astro`, `archive/[slug].astro`: one shared
     article page component is fine — get the doc by slug, render front matter `title` as
     `<h1>`, body via `<Content />`.
   - `about.astro`: body of `about.markdown`, title "About".
   - `archive/index.astro`: intro text from `archive.markdown` + port the Liquid loop into a
     plain `getCollection("archive")` loop (title + date, format `%B %d, %Y` → e.g.
     `May 25, 2026` via `toLocaleDateString` or a tiny helper).
   - `404.astro`: copy the HTML/CSS from `404.html` into the base layout.

5. **Feed (optional, low priority):** `jekyll-feed` currently produces `feed.xml`. If we
   want to keep it, add `@astrojs/rss` and a `src/pages/rss.xml.js` generating from the
   `updates` collection. Otherwise drop it and remove the feed link — note that nothing on
   the site links to it.

6. **Publish pipeline:**
   - `publish.sh`: replace `jekyll build` with `npm install && npm run build`, then rsync
     `dist/` into the `_site` submodule working tree (keep the existing
     `git checkout -- CNAME` safety — with CNAME now in `public/`, dist contains it, so that
     workaround can be dropped), commit, push.
   - `.gitignore`: add `node_modules/`, `dist/`, keep existing Jekyll entries or clean them.
   - (Alternative, noted only: switch to GitHub Actions + `actions/deploy-pages`. Not doing
     this in the initial migration to keep the diff small.)

7. **Cleanup:** delete `_config.yml`, `_includes/`, `_layouts/`, `_data/`, `Gemfile`,
   `Gemfile.lock`, `_topics/`, `_updates/`, `_archive/`, `404.html`, `about.markdown`,
   `archive.markdown`, `assets/css/main.scss` (after porting the `.landing-*` CSS),
   `.sass-cache/`/`.jekyll-cache/` if present. Keep `_site` submodule + `.gitmodules` +
   `.domains`.

8. **Verify:**
   - `npm run build`, then compare the URL inventory of `dist/` against the current
     `_site` (gh-pages) checkout:
     - `/`, `/about/`, `/archive/`, `/404.html`
     - `/topics/00-foia-requests/`
     - `/updates/2026-05-08-did-anyone-ask/`, `/updates/2026-05-11-our-response-to-oklo/`,
       `/updates/2026-05-25-oklo-latest-groves-press-release/`
     - `/archive/00-foia-requests/`, `/archive/10-vipr-reactor/`,
       `/archive/20-waste-tritium/`, `/archive/21-waste-plutonium/`,
       `/archive/50-significant-reactor-events/`
     - `/assets/pdf/Oklo-Texas-Q-A.pdf`, `CNAME`, `robots.txt`
   - Spot-check rendered pages locally (`npm run preview`): sidebar links, markdown
     blockquotes/links, in-page anchors (e.g. `#why-were-foia-requests-filed-for-the-groves-site`
     — GFM slug behavior should match, but verify).

## Known Issues to Preserve as-Is (don't fix in this migration)

- Links to `/topics/20-waste-tritium/` and `/topics/50-significant-reactor-events/` (in
  `_updates/2026-05-11-...` and `_archive/50-...`) point at pages that only exist under
  `/archive/...` — these are already dead links on the live site. Leave them; flag separately.
- `index.markdown` uses a relative link (`updates/2026-05-25-...`); it works because the
  index is at the root. Keep as-is or normalize to absolute paths.

## Out of Scope

- Restyling beyond keeping current visual layout/structure.
- Changing the gh-pages/submodule deploy model.
- Fixing dead links or content edits.
